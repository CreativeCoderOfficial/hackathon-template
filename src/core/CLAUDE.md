# core

Shared code used by every feature. Tiny PRs only: change one thing, open a PR, get it merged right away, announce it in the team chat. Never bundle a core change with feature work. Do not add anything here that only one feature uses.

## Modules

| Module | Exposes |
| --- | --- |
| `env.ts` | `publicEnv`, `hasSupabaseEnv`, `requireSupabasePublicEnv()`, `getServerEnv()` (server only), `isMockEnabled()` |
| `db/client.ts` | `createClient()` for the browser (publishable key) |
| `db/server.ts` | `createClient()` for server code, cookie based session, respects RLS |
| `db/admin.ts` | `createAdminClient()` with the service-role key. Server only, bypasses RLS. Allowed only in a feature's `server/` folder |
| `db/types.ts` | Generated by `npm run db:types`. Do not edit by hand after the first generation |
| `auth/server.ts` | `getCurrentUser()` for server code. Returns `CurrentUser` or null |
| `auth/client.ts` | `getCurrentUser()` for client code, and `upgradeAnonymousUser(email)` |
| `auth/config.ts` | `AUTH_MODE`: `anonymous` (try instantly) or `required` (login wall). Only core reads it |
| `auth/proxy.ts` | Session refresh and anonymous sign-in, used by `src/proxy.ts` |
| `auth/components/` | Starter login, sign-up, password forms, `AccountMenu`, `UpgradeForm` |
| `api/endpoint.ts` | `defineEndpoint()` and the `Endpoint` type used in every `contract.ts` |
| `api/route.ts` | `handle(endpoint, run)`: zod validation, response check, uniform JSON errors |
| `api/client.ts` | `callEndpoint()` and `callOrMock()` (falls back to the mock on network or 5xx errors) |
| `api/errors.ts` | `ApiError`, `unauthorized()`, `backendUnavailable()`, `notImplemented()` |
| `ui/` | Tokens (`tokens.css`), `cn`, Button, Card, Input, Textarea, Label, Spinner, Badge, Checkbox, DropdownMenu, ThemeSwitcher |
| `analytics/` | `track(event, props)` and `AnalyticsProvider`. No-op when `NEXT_PUBLIC_POSTHOG_KEY` is empty |

## Rules

- Features call `getCurrentUser()`. They never read `AUTH_MODE`.
- Add design tokens in `ui/tokens.css` and `tailwind.config.ts`, not in a feature.
- A new env variable goes in `env.ts` and `.env.example` in the same PR. Feature mock flags are the exception: each feature reads its own `NEXT_PUBLIC_MOCK_<FEATURE>` in `mock.ts` and lists it in `.env.example`.
- Core never imports from `src/features/`.
